HUPI has been deployed as release "{{ .Release.Name }}" in namespace "{{ .Release.Namespace }}".

{{- if not .Values.secrets.app.create }}

secrets.app.create is false — make sure a Secret named
"{{ include "hupi.appSecretName" . }}" already exists with
HUPI_APP_DATABASE_URL, HUPI_KEK, and your provider API key(s). See
deploy/k8s/02-secret-app.example.yaml for its exact shape.
{{- end }}
{{- if not .Values.secrets.adminDB.create }}

secrets.adminDB.create is false — make sure a Secret named
"{{ include "hupi.adminDBSecretName" . }}" already exists with
HUPI_ADMIN_DATABASE_URL (the superuser/owner DSN, used only by the
migrate Job). See deploy/k8s/01-secret-admin-db.example.yaml.
{{- end }}

{{- if .Values.migrate.enabled }}

Migrations run automatically as a pre-install/pre-upgrade hook. Check
its status with:
  kubectl get jobs -l app.kubernetes.io/instance={{ .Release.Name }}
{{- end }}

Once the gateway is ready:
  kubectl get pods -l app.kubernetes.io/instance={{ .Release.Name }}

{{- if .Values.ingress.enabled }}
It will be reachable through your ingress controller at:
  http://{{ .Values.ingress.host }}/
(TLS is expected to be terminated by that ingress controller, not this chart.)
{{- else }}
Ingress is disabled — reach the gateway with:
  kubectl port-forward svc/{{ include "hupi.fullname" . }} 8787:{{ .Values.service.port }}
{{- end }}

{{- if .Values.selfcheck.enabled }}

selfcheck.probesConfig ships with a placeholder probe that will fail
until you replace it with questions/answers about facts your own
deployment's memory actually holds — see ARCHITECTURE.md § Retrieval
observability.
{{- end }}

{{- if .Values.adminUI.enabled }}

The admin UI is enabled but has no Ingress by default. Reach it with:
  kubectl port-forward svc/{{ include "hupi.fullname" . }}-admin-ui 8788:80
Create a named operator first with the hupi-admin-ui binary's operator
management commands — see docs/ADMIN_UI.md.
{{- end }}
